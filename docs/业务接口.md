# 老幼共托照护服务接口

业务服务由 `npm start` 启动（`src/server.mjs`），默认监听本机 4400 端口。环境变量：`CARE_PORT`、`CARE_HOST`、`CARE_STATE`（状态文件，默认 `.local/care-state.json`）、`CARE_CATALOG`、`CARE_RECORDS`、`CARE_SEED`（设为 `off` 时不纳入既有合成排班）、`CARE_PEER_URL` / `CARE_PEER_KEY`（家属通知接收端，不配置则不发送通知）。状态原子写入，重启后保留在场人员、照护责任、缺口与待核事项。

所有请求与响应均为 JSON。时间为带时区的 ISO 字符串，时段左闭右开。变更类接口可带 `requestId` 作为幂等流水：同流水同内容重发返回原结果，同流水不同内容返回 409。所有变更串行执行，同一人员的并发交接只会形成一次离站确认。本合成服务不内建身份鉴权，生产部署需独立处理。

## 家属：申请、承诺查询、延长、接送授权

- `POST /applications` 申请照护时段。正文：`familyId`、`from`、`until`、`together`（`required` 必须同时获接收 / `separable` 允许分别安排）、`members` 数组。每位成员：`personId`、`service`、`level`（须与目录一致）、`requiredQualifications`（必须具备的资质）、`pickupAuthorized`（接送授权人，须为家庭监护人）、`emergencyContacts`（至少一名紧急联系人）；可选 `needsAccompaniedDeparture`（儿童默认 true）、`careScope.allowedWorkers`（家属允许的照护范围）。同一被照护人重叠时段的活跃预约返回 409。
- `GET /applications/{id}` 家属看到的接收承诺：每位成员的分区、时段与状态（`pending` / `confirmed` / `reconfirm-needed` / `arrived` / `departed`）。`confirmed` 即明确可履行的承诺；`reconfirm-needed` 附带原因。
- `GET /families/{id}/applications` 家庭全部申请。
- `POST /applications/{id}/extensions` 延长时段：`until`、可选 `memberIds`。延长段与之后已确认的照护一起核查，会挤占他人时 422 且任何人的时段都不变。
- `POST /persons/{id}/pickup-authorizations` 服务中更换授权人：`grant`、`revoke`、`actor`。版本号递增；若被撤销人已完成过交接，保留交接事实并生成待核事项。
- `GET /persons/{id}/presence` 家属查询当前所在分区、负责人与授权版本。

## 站点：受理、排班、到离站、替班

- `POST /applications/{id}/confirm` 站点确认照护条件。`required` 整体核查，任一成员不满足则一人都不确认（422 附失败项）；`separable` 逐人确认，结果含每人状态与失败项。容量、各等级配比、必须具备的资质、家属照护范围逐时段切片核查；一名工作人员同一时段只计入一处配比；存在未解决缺口的分区暂停新接收，其他独立分区不受影响。
- `POST /bookings/{id}/reconfirm` 对待重新确认的预约重新核查。
- `POST /duties` / `POST /duties/{id}/cancel` 排班登记与取消；排班可覆盖多个分区。
- `POST /workers/{id}/absences` 请假；`POST /workers/{id}/qualification-suspensions` 资质暂停。两者都会触发重估：未到站预约转为 `reconfirm-needed`（条件恢复后自动回到 `confirmed`），已到站人员暴露缺口。
- `POST /bookings/{id}/arrivals` 到站登记：`at`、可选 `workerId` 指定负责人（默认取当时符合条件的合格人员）。未确认或待重新确认的预约不能到站。
- `POST /persons/{id}/handovers` 同分区临时交接：`toWorker` 须当时在该分区、持有所需资质且在家属允许范围内。
- `POST /persons/{id}/moves` 临时移到另一分区：`toZone`、`worker`（随行负责人）。原区不再把该照护员算入配比；移动后任一相关分区条件不满足则整体回滚。
- `POST /zones/{id}/substitutions` 替班：`worker`、`from`、`until`。结合在场人数、照护等级、其原有责任（其他分区排班/临时安排）与家属允许范围判断；无法满足时 422，缺口保持向值班负责人暴露。
- `POST /persons/{id}/departures` 接送确认：`staffId`、`guardianId`、`expectedPickupVersion`（交接员页面上看到的授权版本，过期页面 409）。儿童与需要陪同离站的老人仅能交给当前有效的接送人（未授权 403）。
- `GET /persons/{id}/responsibility` 每段照护责任（负责人、分区、起止）；`GET /persons/{id}/departures` 离站记录。
- `GET /zones/{id}/coverage?from&until` 分区逐段覆盖：在场人、配比名额与匹配到的工作人员、未满足项。

## 值班负责人：缺口与待核事项

- `GET /gaps?status=open|closed` 未解决/已恢复缺口（分区、时段、短缺明细）。条件恢复后缺口自动关闭并留痕。
- `GET /review-items?status=pending`、`POST /review-items/{id}/resolve` 待核事项（如交接完成后才收到撤销授权）及其处理。

## 家属通知

配置 `CARE_PEER_URL` 后，确认、待重新确认、恢复确认、离站等承诺变化会投递到家属通知接收端（`notify` 操作，流水号 `notice-N`），发送结果记录在 `GET /notices`；接收端不可达不阻塞业务办理。
